# ゲームの読み込み

公開ゲーム・共有ゲームは、権限を確認するAPIから配信用ZIPを取得し、ブラウザーで展開して隔離iframeで実行します。Driveから直接プレイする構成ではありません。

ゲーム情報とZIPの取得は並列に開始します。共有ゲームへの切り替え時や失敗時は不要な通信を中止します。ZIP展開は全エントリーのパス・重複・サイズ制限を確認した後、最大4ファイルずつ並列に処理します。非圧縮ファイルは元のバッファーを参照し、不要なコピーを減らします。展開後のファイル順・GodotのHTMLと関連ファイル名・隔離実行の制約は維持します。

上限はZIP 50MB、展開後合計200MB、500エントリーです。大量のファイルを無制限に同時展開しません。権限確認を省略するキャッシュや、非公開ゲームを公開URLへ置く変更は行っていません。

実際の起動時間は通信速度、ZIPの大きさ、端末性能、Godotの初期化時間に依存します。今回の変更は通信待ちと展開処理の効率を改善するもので、特定の秒数や倍率を保証するものではありません。Godotでは不要な素材の除外やリリース用Web書き出しで配信サイズを減らすと、初回読み込みにも効果があります。

検証: mixed stored/deflate ZIPの内容一致、重複・パストラバーサル・サイズ不一致の拒否、ブラウザーでの公開/共有ゲーム再生と隔離プレビュー。

## バイナリ転送による追加高速化

通常のプレイヤーと本人用プレビューでは、展開したファイルのArrayBufferをMessageChannelとpostMessageで隔離iframeへ転送します。sandboxは`allow-scripts`のみです。転送先のiframe内でBlob URLを作るため、親ページと同じオリジンの権限を与えずにWASM・PCK・JS・CSSを読み込めます。

大きな素材のBase64変換、巨大なHTML属性・JavaScript文字列への埋め込み、再デコードを省きます。転送後は親側のバッファーがdetachされるため、同じMapを再利用せず、新しい読み込みで取得したデータを渡してください。Blob URLの寿命はiframeの文書に限定され、ページ移動や再読み込みで破棄されます。認証情報や親DOMへのアクセスはゲームへ渡しません。外部通信は引き続きCSPで禁止します。

`binary sandbox loading`ブラウザーテストでは12MiBの合成PCK、最小WASM、JS/CSSを用いて、旧方式と新方式を同じゲーム側の完了通知まで比較します。測定値は`test-results/binary-loading-performance.json`へ出力します。これは転送後の起動処理の比較で、実ゲームの通信・Godot初期化全体の速度保証ではありません。
