# 投稿済みゲームのファイル変更

アカウント → 投稿したゲーム → 管理・編集 → ゲームファイルを変更。HTML、ZIP、Web書き出しの複数ファイル（最大50MB）を既存と同じ検証・ZIP変換で送信します。タイトル、タグ、サムネイル、公開範囲、予約日時、ゲームURLは保持します。一般投稿者の公開・限定公開は再審査（pending）、下書きはdraft、信頼済み投稿者はapprovedです。審査中は公開再生できず、本人は確認できます。

## 導入

既存migrationの後に `202610040018_package_replacement_tag_limit.sql` を適用し、Edge Function portalをデプロイします。タグ上限もUI・API・DBのすべてで22個に更新します。

## 安全性と通信障害

既存/uploadにpackage_revision（UUID）を送信すると差し替えになります。replace_prepare / replace_completeはEdge内部専用で、通常JSON APIからは実行できません。認証・BAN・所有者・投稿権限・状態を保存前と保存後に検証します。updated_atによる競合検知で途中の編集や審査、削除と競合した場合は更新を拒否します。

新しいZIPはリクエストごとのサーバー乱数を含む別のStorageキーに保存し、検証・Drive保管後にDBを切り替えます。失敗時に既存ファイルを上書きしません。成功応答を失った場合は本人の投稿一覧のpackage_revisionが送信したUUIDと一致する場合だけ成功と判断します。

旧Drive ZIPは非公開アーカイブとして残ります（保存容量を消費します）。旧Storage ZIPは成功後に削除を試みます。通信障害・競合・BANで未使用の非公開ファイルが残る場合があります。参照済みか不明な場合に新しいファイルを誤って削除しないためで、自動削除の永続キューは今回含みません。削除する前にDB参照の有無を確認してください。
