# 審査通知・グループ作品・編集保護・更新履歴・読み込み状況

## セットアップ

SQL Editorで `202610100031_review_notifications.sql` → `202610100032_group_catalog.sql` → `202610100033_game_release_history.sql` の順に適用し、Pagesを更新します。既存のEdge Functionの認証済みRPCと文字列フィールドを使用するため、追加の秘密情報やEdge Functionの変更はありません。

## 審査結果のお知らせ

`portal_private.review_notifications` に投稿者・作品・審査結果・理由・通知日時・既読日時を保存します。審査待ちから承認／却下、および公開停止への変更を通知します。下書き、信頼済み投稿者の自動承認は審査結果通知を作りません。過去の結果は遡って通知しません。

アカウント画面に最新100件を表示します。`user.submissions` は認証済み本人の通知だけを返し、`read_notification_id` が指定された場合も本人の通知のみ既読にします。既読状態はDBに保存されます。ゲーム／アカウント削除に連動して通知を削除します。

## グループ内の作品一覧

アカウント画面の所属グループ選択と作品名検索から閲覧できます。`user.shared.games` に `group_id` を指定すると、現在有効な所属、投稿者の所属と利用状態、グループ共有、承認、配信ファイル、公開日時をサーバーで検証します。下書き・審査待ち・予約前・他グループ作品は返しません。所属／共有先のID一覧も返しません。一般ユーザーの自主入退出や管理権限付与はできません。

## 編集中の変更を保護

投稿・作品編集（本人／全権管理者／担当グループ管理者）の入力、タグ、AI申告、ファイル選択、ドラッグ＆ドロップを監視します。未保存または送信中にページを離れる場合は確認します。ページ更新／タブを閉じる際の確認文はブラウザー標準です。正常保存後は確認を解除し、失敗時は入力を保持します。入力内容やパスワード、ファイルをブラウザーストレージへ保存する機能ではありません。ブラウザー強制終了やOSによる終了からの復元はできません。

## ゲーム更新履歴

投稿・編集フォームの「このバージョンの更新内容」は任意、最大2,000文字です。既存の禁止語・URL禁止を適用します。`portal_private.game_releases` は作品IDとバージョンの複合主キーを持ち、承認済み・配信ファイルあり・下書き以外の状態で記録します。同じバージョンの更新内容は上書きされ、別バージョンにすると履歴が増えます。記録日時はそのバージョンを初めて記録した日時です。既存作品はmigration適用時点から記録します。

本人の編集画面と、既存の閲覧認可を通過した作品詳細に最新100バージョンを表示します。未承認の更新内容は公開履歴に記録しません。履歴は過去のZIPを保存／復元する機能ではなく、ゲーム削除時に消えます。

両テーブルはprivate schema・RLS有効・全クライアントへの直接権限なしです。既存RPCのサーバー認可後にのみ参照／更新します。新しいprivate helperと旧RPCの直接実行も禁止します。service roleをブラウザーへ渡しません。

## ゲームの読み込み状況

ファイル取得（受信MB、Content-Lengthがある場合のみ割合）、展開（完了ファイル数／総数）、画面の準備・起動、経過秒数を表示します。最大50MBの受信制限を維持します。メタデータとZIPの並列取得・展開、アクセス認可完了前の実行禁止、隔離プレイヤーを維持します。ゲーム内部のGodotエンジン初期化・シーン生成の進捗はゲーム側の表示に従います。「ゲームを表示しました」は画面の準備完了であり、エンジン全体の進捗100%ではありません。
