# 入力内容の制御・AI利用申告・プロフィールアイコン

## 配置と公開

SQL Editorで migration 027 → 028 → 029 を順に実行し、最新の `supabase/functions/portal/index.ts` を Edge Function `portal` にデプロイしてから、Pagesを公開する。環境変数の追加は不要。既存のゲーム・アカウントを一括削除・変更する処理はない。

## 禁止語とURL

`portal_private.content_rules` は禁止語マスタ（id、term、normalized、match_mode、category、is_active、created_at、updated_at）。RLSを有効化し、anon / authenticated / service_roleにはテーブル・内部関数への直接アクセスを許可しない。サービス側の `portal_api` 経由でも有効な全権管理者セッションを検証する。一般ユーザー・グループ管理者は設定を読んだり変更したりできない。

全権管理者は管理画面の「禁止語の管理」で追加・編集・無効化できる。有効・無効の合計は1,000件、語句は1〜80文字。解除は「無効」に変更する。初期データはmigration 027のseedに記載し、`on conflict(normalized) do nothing`で重複を防ぎ、無効にした語を再有効化しない。初期語は明確な罵倒・脅迫、差別的な蔑称、性的表現を小さな集合から始める。「バカ」「殺す」などゲーム説明で使われやすい単語や、人の属性そのものは初期語に含めない。

対象はログイン用アカウント名、表示名、ゲーム名・説明・操作説明・バージョン・素材の権利表記、グループ名・概要、タグ名・slug・カテゴリ、リスト名。プロフィールに今後自由記述フィールドを追加する場合もDBトリガーの対象に追加すること。パスワード、ログイン入力、報告内容、審査理由、秘密情報は対象外。登録済みの内容は変更したフィールドだけ検査し、既存アカウントのログインやBAN/KICKを妨げない。

URLは素材の権利表記・提供元欄のみ許可し、それ以外の対象欄では拒否する。HTTP等のスキーム、www、一般的なTLDのドメイン（メールアドレスを含む）、IPv4リンクを検出する。`index.html`・`.js`・`.wasm`など通常のファイル名やバージョン番号は許可する。権利表記のURLはクリックできないテキストとして表示する。

Unicode NFKC、英字の小文字化、ゼロ幅文字の除去を行う。「含まれていれば検出」は空白・句読点を除去した部分一致、「英単語一致」は英数字の単語単位の一致で、無関係な英単語の一部だけで検出しない。管理者が正規表現を登録する形式ではない。

禁止語は `content_blocked`、URLは `url_not_allowed` を返し、画面に理由を表示する。DBトリガーとRPCの例外処理により、拒否時はそのリクエストの変更・関連監査記録もロールバックする。入力は修正できるようフォームに残し、APIや監査ログに拒否した本文・検出語を返さない。設定変更はルールIDと操作・有効状態のみ監査する。

語句判定は文脈を理解しないため、引用や固有名詞の誤判定、未登録語や別の書き方の見逃しがあり得る。ルールは運用しながら調整する。ゲームファイル内の文章・画像・音声を自動審査する機能ではない。URL禁止や禁止語はXSS対策の代替にはならず、安全なテキスト表示・ゲームの隔離・既存の審査を維持する。[OWASP Input Validation](https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html) を参照。

## AI利用申告

`game_submissions.ai_used`（boolean / null）、`ai_types`（text[]）に保存する。種類は image（画像）、audio（音声・音楽）、text（テキスト）、code（プログラム）、other（その他）。利用ありの場合は1種類以上、最大5種類、重複・未知の値を拒否する。利用なしの場合は空配列。旧投稿のnullは未申告を表し、未使用と推測しない。

投稿フォームのチェックボックスで利用の有無を指定し、利用ありのときだけ種類を表示する。投稿後の一括編集でも変更可能。審査・担当グループの管理画面に表示し、ゲーム詳細には申告された内容を表示する。AI利用を理由とした投稿・公開・アクセスの制限はない。所有権、公開範囲、通常の審査フローは同じ。

## アイコン

`assets/avatars.js` がフロントの36種類の共通カタログ。DBの `users_avatar_key_check` と `portal_private.avatar_key` も同じキーを許可する。プロフィールと作者ページで共通表示する。任意の画像URLやファイルは受け付けない。
