# 管理・モバイルUIと表示名

管理メニューから審査・ユーザー・グループ・報告・タグ・禁止語へ移動できます。権限のあるセクションだけ表示し、担当グループ管理者に全体のユーザー管理を追加しません。投稿・ユーザーの検索と状態フィルターは現在取得した最大100件が対象です。前後の100件を切り替えるボタンを併用してください。グループ検索は認可されたグループだけが対象です。検索で権限は変わりません。

スマホの投稿・作品編集は保存ボタンと進捗を同じパネルに表示し、下端で操作できます。入力は16px以上、主要操作は44px以上です。送信中のフォーム無効化、失敗時の入力保持、二段階削除確認を維持します。

## サービス名の変更

`assets/brand.js` の `brand.name`（サービス名）と `brand.eyebrow`（見出し上部の短い文）を変更し、通常どおりビルド・公開してください。名前は空欄不可・80文字以内・改行不可です。ビルド時にサイトのHTMLの見出し・タイトル・フッター・アクセシビリティ表記へ反映し、HTML特殊文字をエスケープします。ゲーム詳細・作者プロフィールの動的タイトル、利用同意メッセージもこの設定を参照します。

ソースHTMLの従来名はビルド用の共通置換位置です。個別に変更せず、この設定を使ってください。公開設定は秘密情報を含めません。リポジトリ名、URL、独自セッションの保存キー、規約の同意バージョン、DB・Driveフォルダー名は表示名の変更で書き換えません。投稿されたゲーム本体・ゲーム名・ユーザーの文章も変更しません。運営者や規約内容の変更は別途確認してください。

## ゲーム読み込み

公開・共有パッケージは従来どおり個別にサーバー認可します。ZIP取得後の検証・展開を、作品メタデータの取得完了を待たず並行して行います。メタデータとZIP双方が成功するまでゲームは実行しません。失敗時は残りの通信を中止し、非公開ファイルや失効した共有のコピーを永続キャッシュに保存しません。ZIP上限・展開上限・隔離iframeを維持します。

この改善はメタデータ取得待ちとZIP展開が重なる場合の待ち時間を減らします。Godot本体のWASM初期化やプロジェクトの素材サイズは別の要因なので、すべてのゲームで同じ短縮時間は保証しません。変更はフロントエンドのみで、SQL・Edge Functionの追加デプロイは不要です。
名称変更時は、ビルドが表示名から算出した版番号を静的ページとモジュールのURLへ自動追加し、以前の名称がブラウザーのキャッシュに残ることを防ぎます。
