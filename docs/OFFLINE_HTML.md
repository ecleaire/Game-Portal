# 完全オフライン HTML版 GAME PORTAL

PC版Google Chrome（Windows / macOS）推奨です。配布ZIPを展開し、`GAME-PORTAL.html` をChromeで開きます。画面・Pyxel・Pyodide・Python標準ライブラリーをHTMLに同梱しています。使用中のCDN・Supabase・Google Drive接続、アカウント登録は不要です。

## 使用手順

1. 「設定」→「フォルダーを指定」で、ゲーム専用のローカルフォルダー、またはOSからアクセスできるNAS共有フォルダーを選び、読み取りを許可します。初期状態では閲覧・プレイのみ可能です。
2. 投稿・編集する人は、設定の「ゲームの追加・編集を有効にする」をオンにして書き込みを許可します。この設定はこのPCのChrome内に保存します。
3. 「投稿」でHTML・WebゲームZIP・Pyxel PYXAPP、またはWeb書き出しフォルダー一式を保管フォルダーへコピーします。投稿元のファイルは変更しません。
4. 各ゲームの「編集」で表示名・タグ・サムネイル・開発環境を変更し、「保存」を押します。タグは既存GAME PORTALと同じ8分類の候補からクリックで選択でき、独自タグも入力できます。ゲーム名・タグ・開発環境で検索し、複数タグではすべてを持つ作品に絞り込みます。
5. 「プレイ」で起動します。Pyxelは準備後にゲーム画面をクリックして開始します。
6. 別の人が追加・編集した場合や、フォルダーへ直接ゲームを追加・移動した場合は「再読み込み」を押します。アクセス許可が切れたら設定で再接続、またはフォルダーを指定し直してください。

対応形式はHTML/HTM、HTMLを含むZIP、Pyxelの `.pyxapp`。EXE、ネイティブ用ZIP、Pythonの任意パッケージを後からネット取得する作品には対応しません。Pyxel 2.9.9 / Pyodide 314.0.4を同梱します。別バージョン固有の機能を使う作品は互換性を確認してください。

GodotはWeb書き出しの全ファイルをZIPまたはフォルダーで投稿してください。Scratch/TurboWarpは素材を含むHTMLまたはZIPを使用します。ZIPは50MB、展開後200MB・500ファイルまで。HTMLフォルダーも200MB・500ファイルまで。Webゲームの外部HTTP通信・ダウンロード・親画面へのアクセスは許可しません。スレッド必須のGodot書き出しや外部サーバー必須の作品は動作しません。

## ゲームごとの設定ファイル

投稿時に、起動ファイルの隣へ `<起動ファイル名>.gameportal.json` を作成します。既存フォルダーのゲームは、初めて「編集」→「保存」した時点で作成します。画面で保存先を確認できます。サムネイルはWebPへ変換して同じJSON内へ埋め込みます。

```text
GAME-PORTAL.html
ゲーム保管フォルダー/
  MyGame.html
  MyGame.html.gameportal.json
  game.pyxapp
  game.pyxapp.gameportal.json
  .gameportal/
    history/作品ID/保存ごとのUUID.json   設定の変更前・変更後の復旧用履歴
    library.json                       旧版が作成した場合のみ残る管理情報
    thumbnails/                        旧版の画像（存在する場合）
    saves/                             旧版の共有セーブ（新バージョンは書き換えない）
```

```json
{
  "schema": 1,
  "id": "0123456789abcdef0123456789abcdef",
  "title": "ゲームの名前",
  "tags": ["アクション", "お気に入り"],
  "developmentEnvironment": "Godot 4.5",
  "thumbnail": null,
  "updatedAt": "2026-10-14T00:00:00.000Z"
}
```

タグ候補は https://ecleaire.github.io/Game-Portal/#games の公開タグ77件を取り込んだものです。実行中にサイトへ問い合わせず、HTMLに同梱した候補を使用します。

通常はHTML画面から編集してください。JSONを直接編集した後は画面で「再読み込み」を押してください。`schema` と `id` は変更しないでください。旧版の `.gameportal/library.json` と画像は読み取り互換を維持し、編集保存時に対象ゲームだけ新形式へ引き継ぎます。旧ファイルは自動削除しません。

## NAS共有時の対策と限界

ゲーム本体・設定・画像はNASで共有し、セーブは各PCのChromeプロファイル内のIndexedDBへ保存します。共有フォルダーへ新しいセーブを書き込まないため、別PCの人の進行状況を上書きしません。同じPC・同じChromeプロファイルを使う人同士はセーブを共有します。別の保管フォルダーは、同名のゲームや同じ作品IDがあっても保存領域を分離します。

- 初期状態は閲覧・プレイのみです。投稿・編集する人だけ設定をオンにします。この設定は操作ミスを減らす機能で、認証やアクセス制御の代わりにはなりません。権限を制限する場合はNAS側でも閲覧者を読み取り専用にしてください。
- 設定を保存するときは排他書き込みを要求し、書き込み開始前にも元の内容との一致を確認します。既に更新されていれば保存せず、再読み込みを案内します。
- 上書き前に `.gameportal/history/作品ID/UUID.json` へ変更前と変更予定の設定を残し、保存後にも内容を読み戻して確認します。履歴ファイルには `gamePath`、`before`、`after`、`savedAt` が入ります。手動復旧する場合は、対象パスを確認し、`before` または `after` の文字列をJSONとして元の設定ファイルへ保存します。履歴は保存試行の記録であり、保存完了の証明ではありません。
- NAS切断や保存失敗時は自動で上書きを再試行しません。接続を復旧し、最新の設定と履歴を確認してください。履歴は自動削除しないため、NASの容量管理・バックアップも行ってください。
- 投稿中は専用マーカーで一覧から隠し、コピーと設定保存の完了後に表示します。失敗時はその投稿で作成したフォルダーだけを削除します。強制終了等で `.gameportal-uploading` が残ったフォルダーは表示しません。元のゲームを確認して再投稿してください。
- 壊れた設定ファイルや同じ作品IDの重複は該当カードで案内し、そのゲームのプレイ・編集を止めます。他の正常なゲームは利用できます。同じゲームを別作品として複製する場合は「投稿」を使用してください。
- 同じChromeプロファイルの別タブでは、同じゲームを同時起動できないようにしています。セーブ失敗時は未保存内容を保持して終了を止め、再試行やセーブ書き出しができます。

ブラウザーの排他処理は、別PC間のNASロックを保証しません。**同じゲームの設定は同時編集しない運用にしてください。** 別PCの同時編集を厳密に制御するには、NAS上の管理サーバー等が必要です。NASのスナップショット・定期バックアップも併用してください。実NASのSMB接続、OSの権限設定、切断・復旧時の挙動は実機確認が必要です。

## セーブのバックアップと移行

HTML/ZIPゲームのlocalStorage相当のデータを各PCに保存します（約500KBまで）。プレイ画面の「セーブ書き出し」でJSONとしてバックアップし、「セーブ読み込み」で確認後に取り込めます。異なるゲームの書き出しファイルは拒否します。ゲーム独自のIndexedDB・CookieやPyxelの独自セーブファイルは自動保存の対象外です。

旧版の `.gameportal/saves/作品ID.json` は削除も自動取り込みもしません。必要な人だけ、該当ゲームを起動して「セーブ読み込み」からそのファイルを選択してください。読み込みはこのPCのセーブを置き換えます。既存の進行状況があれば先に書き出してください。

Chromeの閲覧データ削除・プロファイル変更・HTMLの配置先変更によって、ローカルセーブを参照できなくなる場合があります。別PCへの移行やランチャーの配置変更前にも書き出してください。

## 別PCへの持ち運び

`GAME-PORTAL.html` と保管フォルダー全体をコピーするか、同じNASを利用します。初回にChromeから保管フォルダーを選び直してください。PC固有の絶対パスはゲーム設定に保存しません。Chromeのアクセス許可は別PCへ引き継げません。ゲーム・タグ・画像は保持され、セーブは必要な人が書き出し・読み込みで移行します。

設定ファイルを作成したゲームは、ゲームと設定を一緒にフォルダーごと移動すると作品IDを維持します。ただし別の保管フォルダーはローカルセーブを分離するため、セーブも移す場合は書き出し・読み込みを使用してください。ゲームファイル自体を改名する場合は、設定ファイル名も `<新しいゲームファイル名>.gameportal.json` に合わせてください。改名・移動前にバックアップしてください。

ランチャーHTMLはゲーム保管フォルダーの外に置いてください。保管フォルダーの名前・一覧情報・設定履歴はゲーム内へ渡さず、実行データのみを隔離iframeへ渡します。Chromeのフォルダー許可画面は手動操作が必要です。モバイルChrome・Safari・Firefoxはこの版の対象外です。

## 開発・配布ビルド

```sh
npm ci
npm run offline:prepare
npm run offline:build
npm run offline:test
```

`offline:prepare` は固定バージョンの公式配布物を取得し、`offline-html/runtime-lock.json` のSHA-256を検証します。初回ビルド準備のみネット接続が必要です。Node.js 22以上を使用し、Node.js 24でプロキシを使う環境では `NODE_USE_ENV_PROXY=1` を設定してください。取得済みデータは `.tools/offline-runtime`、変更したキャッシュは `OFFLINE_RUNTIME_CACHE` で指定します。通常のビルドはネット取得を行いません。出力は `offline-release/GAME-PORTAL-HTML.zip` と単体HTMLです。ランタイムのライセンス表示もZIPへ含めます。Pagesの本番サイトとデータベースは変更しません。
