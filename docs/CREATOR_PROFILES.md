# 作者プロフィール

ゲーム詳細・投稿済み作品の編集画面にある「作者名 のプロフィール」から、表示名・アカウントアイコン・自己紹介・他の投稿作品を閲覧できます。表示名・アイコン・自己紹介はアカウント設定で変更します。自己紹介は任意、1,000文字以内で、改行を維持するプレーンテキストです。URLと禁止語はサーバー側で拒否し、プロフィール全体の保存を取り消します。

`profile/?game=<公開slug>` は元のゲームを閲覧できる人だけが開けるプロフィールです。元のゲームが削除・非公開化された場合、そのリンクも利用できなくなります。プロフィール用にログインIDやグループ所属、フォロワー、いいねした人の一覧を公開しません。

`social.creator` は Edge Function の既存セッション検証と SQL の実際のゲーム閲覧権限を使用します。作品は新しい順で25件ずつ読み込みます。公開日時・審査・個別共有・グループ所属を毎回確認し、閲覧できない作品の名前・URL・件数を返しません。限定公開作品は作者本人以外のプロフィール一覧には表示しません。作者本人は自分の下書きなども開けます。限定公開ゲームからプロフィールを開いても、他の限定公開ゲームは列挙しません。

導入は `202610090025_creator_profiles.sql` を適用し、`portal` Edge Function を更新後に Pages を公開してください。既存のテーブル構造と投稿・審査処理は変更しません。内部の旧 API 関数は直接呼び出せず、公開 RPC は service_role のみ実行可能です。

検証: `tests/profiles.test.mjs` は匿名・本人・共有相手・第三者、共有解除、BAN、無効セッションを検証します。`tests/browser/library.spec.mjs` は実際のゲーム画面から作者プロフィール、他のゲームへの移動と390px/1440pxの表示を検証します。

自己紹介の追加は `202610100030_profile_bio.sql` を適用してからPagesを公開します。`users.bio` は非公開テーブル内に保存し、`user.profile` はセッション本人のみ更新可能です。既存のプロフィールAPIが作品の閲覧を許可した場合だけ作者の自己紹介を返します。旧クライアントがbioを送らない場合は現在の自己紹介を維持します。追加のEdge Function actionや環境変数は不要です。
